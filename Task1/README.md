# Task1. Обратная матрица методом Гаусса с выбором главного элемента по всей матрице

## Как собрать и запустить

```
make
./a.out n m k [файл]
```

* `n` — размер матрицы,
* `m` — сколько строк и столбцов печатать (чтобы не залить экран при больших `n`),
* `k` — номер формулы, по которой строится матрица; `k = 0` означает «читать из файла»,
* `файл` — имя файла с матрицей (нужен только при `k = 0`).

Формулы (нумерация с единицы):

| k | a(i, j)          |
|---|------------------|
| 1 | n − max(i, j) + 1 |
| 2 | max(i, j)         |
| 3 | \|i − j\|         |
| 4 | 1 / (i + j − 1)   |

Примеры:

```
./a.out 4 4 0 a.txt     # матрица из файла a.txt
./a.out 5 5 1           # матрица по формуле 1
./a.out 1000 5 4        # матрица 1000x1000, печатаем угол 5x5
```

Программа печатает исходную матрицу, обратную, невязку `||A·A⁻¹ − E||` и время счёта.
Если матрица вырождена, печатается сообщение об этом.

## Объяснение «на пальцах»

### Что вообще требуется

Обратная матрица `A⁻¹` — это такая матрица, что `A · A⁻¹ = E`, где `E` — единичная
(единицы по диагонали, нули везде). Это как обратное число: у числа 5 обратное 1/5,
потому что 5 · 1/5 = 1. У матриц то же самое, только умножение хитрее.

### Главная идея (самая важная мысль)

Пишем рядом две матрицы: слева нашу `A`, справа единичную `E`:

```
[ A | E ]
```

Дальше мы делаем со строками простые действия: **меняем строки местами**,
**делим строку на число**, **вычитаем одну строку из другой**. Причём каждое
действие делаем сразу в обеих половинах — и слева, и справа.

Наша цель: замучить левую половину так, чтобы она превратилась в единичную матрицу.
И вот фокус: когда слева получится `E`, справа сама собой окажется `A⁻¹`:

```
[ A | E ]  →  →  →  [ E | A⁻¹ ]
```

Почему так? Потому что все наши действия со строками — это умножение слева на
какую-то матрицу `M`. Слева мы получили `M·A = E`, значит `M = A⁻¹`. А справа
то же самое `M` умножилось на `E`, то есть справа лежит ровно `M = A⁻¹`. Всё.

### Как именно мучаем матрицу (шаг за шагом)

Идём по шагам `k = 0, 1, 2, ..., n−1`. На шаге `k`:

1. **Ищем главный элемент.** Смотрим на весь оставшийся кусок матрицы (строки и
   столбцы с номерами от `k` до конца) и находим там самое большое по модулю число.
2. **Ставим его в угол** — на место `(k, k)`. Для этого меняем местами строки и
   меняем местами столбцы.
3. **Делим всю строку `k` на этот элемент** — теперь на месте `(k, k)` стоит 1.
4. **Вычитаем строку `k` из всех остальных строк** с такими коэффициентами, чтобы
   во всём столбце `k` стали нули.

После `n` таких шагов слева стоит единичная матрица, а справа — ответ.

### Зачем искать «самый большой» (выбор главного элемента)

Мы делим на элемент `(k, k)`. Если там окажется ноль — деление рухнет. Если там
окажется очень маленькое число — мы поделим на почти ноль, получим гигантские числа,
и компьютер потеряет точность (у `double` всего ~16 значащих цифр). Поэтому мы
специально выбираем самое большое по модулю число: делить на большое — безопасно.

«По всей матрице» значит, что мы ищем этот элемент не только в столбце и не только
в строке, а во всём оставшемся прямоугольнике — это самый надёжный из вариантов.

### Хитрость с перестановкой столбцов

Перестановка **строк** — честная операция, мы делаем её сразу в обеих половинах.
А вот перестановка **столбцов** — это перенумерация неизвестных, и делать её в
правой половине нельзя. Из-за этого в конце строки ответа оказываются перепутаны.

Поэтому мы заводим массив `col`, который помнит, куда какой столбец уехал, и в самом
конце расставляем строки ответа по своим местам:

> строка `k` посчитанной матрицы — это на самом деле строка `col[k]` обратной матрицы.

Это последний цикл в `inverse.cpp`.

### Как проверить, что всё не врёт

Умножаем исходную матрицу на ту, что получилась, и вычитаем единичную:
`||A·A⁻¹ − E||`. Это число называется **невязкой**. В идеале оно равно нулю, на
практике из-за округлений получается что-то вроде `1e-15` — это отлично. Если
невязка большая (например, 0.1) — в программе или в матрице что-то не так.

### Сколько это работает

Три вложенных цикла, поэтому примерно `n³` операций. Матрица 1000×1000 считается
несколько секунд, 100×100 — мгновенно.
