--------------------------------------------------------------------------------
0. ЧТО ТРЕБУЕТСЯ И ЧТО СДЕЛАНО
--------------------------------------------------------------------------------

Дана функция f(x, y) на прямоугольнике [a,b] x [c,d] и сетка узлов
x_1,...,x_nx по первой переменной и y_1,...,y_ny по второй. Надо построить
интерполяционный многочлен по формуле Ньютона (в двумерном случае это
интерполяция тензорными произведениями) и нарисовать три поверхности:
саму функцию, приближение и погрешность.

По § 1.5.3 базисные функции берутся такие:

    u_i(x) = (x - x_1)(x - x_2)...(x - x_{i-1}),   i = 1..nx,
    v_j(y) = (y - y_1)(y - y_2)...(y - y_{j-1}),   j = 1..ny,

(пустое произведение равно 1), базис в пространстве функций - их тензорные
произведения

    w_ij(x, y) = u_i(x) v_j(y),

а приближающая функция ищется в виде

    P(x, y) = sum_{i=1..nx} sum_{j=1..ny} c_ij u_i(x) v_j(y).

Функционалы из § 1.5.3 - это значения в узлах, матрицы A и B единичные,
поэтому коэффициенты c_ij получаются просто: это СМЕШАННЫЕ (двойные)
разделённые разности

    c_ij = f[x_1, ..., x_i ; y_1, ..., y_j].

Построенный многочлен точно попадает в значения функции во всех узлах
сетки: P(x_i, y_j) = f(x_i, y_j).

Сборка через qmake:

    cd путь/к/task3_yarik

    qmake6 graph3d.pro && make       # Qt6

Сборка одной командой, без qmake (Qt5 на Ubuntu):

    /usr/lib/qt5/bin/moc window3d.h -o moc_window3d.cpp && \
    g++ -O2 -Wall -Wextra -fPIC -std=c++17 \

        main.cpp window3d.cpp functions2d.cpp newton2d.cpp moc_window3d.cpp \
        -o graph3d -lQt5Widgets -lQt5Gui -lQt5Core

Запуск - девять аргументов командной строки:

    ./graph3d  a  b  c  d  nx  ny  mx  my  k

    a < b    - границы области по x (double);
    c < d    - границы области по y (double);
    nx, ny   - число узлов интерполяции по x и по y (>= 2);
    mx, my   - число точек сетки, по которой рисуется поверхность (>= 2);
    k        - номер приближаемой функции, 0..7.

Без аргументов берутся значения по умолчанию: -1 1 -1 1 10 10 40 40 7.

Примеры:

    ./graph3d -1 1 -1 1 10 10 40 40 7    # функция Рунге в 2D
    ./graph3d -1 1 -1 1 20 20 60 60 6    # e^(x^2-y^2), приближение уже точное
    ./graph3d -2 2 -2 2 8 8 32 32 4      # корень (негладкая в нуле функция)

Список функций (номер k):

    k = 0   f(x,y) = 1
    k = 1   f(x,y) = x
    k = 2   f(x,y) = y
    k = 3   f(x,y) = x + y
    k = 4   f(x,y) = sqrt(x^2 + y^2)
    k = 5   f(x,y) = x^2 + y^2
    k = 6   f(x,y) = e^(x^2 - y^2)
    k = 7   f(x,y) = 1/(25(x^2 + y^2) + 1)


--------------------------------------------------------------------------------
2. УПРАВЛЕНИЕ
--------------------------------------------------------------------------------

    0      - циклически сменить номер функции k (возмущение p сбрасывается);
    1      - циклически сменить режим:
                 исходная функция f(x,y)
                 интерполяционный многочлен Ньютона P(x,y)
                 погрешность f(x,y) - P(x,y);
    2      - увеличить масштаб (отображаемый прямоугольник сжимается вдвое
             к своей середине, s := s+1);
    3      - уменьшить масштаб (растягивается вдвое, s := s-1);
    4      - удвоить число узлов интерполяции nx и ny (предел 64);
    5      - уменьшить nx и ny вдвое (минимум 2);
    6      - увеличить возмущение: значение в центральном узле сетки
             получает добавку p*0.1*max|f|, p := p+1;
    7      - то же в обратную сторону, p := p-1;
    8      - повернуть камеру влево на pi/12;
    9      - повернуть камеру вправо на pi/12;
    +      - удвоить сетку рисования mx, my (предел 128);
    -      - уменьшить сетку рисования вдвое (минимум 8);
    Up     - поднять камеру над плоскостью;
    Down   - опустить камеру;
    Ctrl+Q - выход.

Всё, что нужно для отчёта, выводится и в окно (левый верхний угол), и в
строку состояния: номер и формула функции, текущий режим, nx, ny, mx, my,
масштаб s, возмущение p, величина max{|F|} по нарисованной поверхности и
углы камеры. Значение max{|F|} и время построения печатаются ещё и в
консоль.

Важно не путать две сетки:
  - nx, ny - это УЗЛЫ ИНТЕРПОЛЯЦИИ, по ним строится многочлен;
  - mx, my - это сетка ТРИАНГУЛЯЦИИ, по ней только рисуется картинка
    (она никак не влияет на само приближение).

--------------------------------------------------------------------------------
4. КАК СЧИТАЮТСЯ КОЭФФИЦИЕНТЫ c_ij
--------------------------------------------------------------------------------

Смешанная разделённая разность f[x_1,...,x_i ; y_1,...,y_j] - это обычная
разделённая разность по x, применённая к разделённой разности по y (порядок
не важен, результат тот же). Поэтому таблица считается в ДВА прохода прямо
на месте, в массиве coeffs:

Шаг 0. coeffs[i*ny + j] = f(x_i, y_j).

Шаг 1 (по x). Для каждого уровня level = 1..nx-1 и для каждого i от nx-1
вниз до level:

    coeffs[i][j] := ( coeffs[i][j] - coeffs[i-1][j] ) / ( x_i - x_{i-level} )
    сразу для всех j = 1..ny.

После этого прохода в строке i стоят разделённые разности порядка i-1 по x.

Шаг 2 (по y). Теперь то же самое внутри каждой строки i: для level = 1..ny-1
и для j от ny-1 вниз до level:

    coeffs[i][j] := ( coeffs[i][j] - coeffs[i][j-1] ) / ( y_j - y_{j-level} ).

Проход "сверху вниз" (от большого индекса к меньшему) нужен, чтобы не
затереть ещё не использованное значение - это тот же приём, что и в
одномерной формуле Ньютона.

Стоимость построения: O(nx^2 * ny + nx * ny^2) действий, памяти O(nx*ny).

Вычисление значения - двойная схема Горнера:

    P(x,y) = g_1(y) + (x - x_1)( g_2(y) + (x - x_2)( ... ) ),
    g_i(y) = c_i1 + (y - y_1)( c_i2 + (y - y_2)( ... ) ).

Это O(nx*ny) умножений на одну точку, без явного вычисления произведений
u_i(x) и v_j(y) (так устойчивее по округлениям).


--------------------------------------------------------------------------------
5. ПОЧЕМУ УЗЛЫ ЧЕБЫШЁВА И ПОЧЕМУ ПОРЯДОК ЛЕЖА (важное место)
--------------------------------------------------------------------------------

(1) Узлы. Если брать равномерные узлы, то многочленная интерполяция высокой
степени разваливается из-за эффекта Рунге - у краёв области появляются
огромные колебания. Поэтому узлы берутся чебышёвские (нули многочлена
Чебышёва):

    t_i = (a+b)/2 + (b-a)/2 * cos( pi (i + 1/2) / n ),   i = 0..n-1.

Насколько это важно, видно из опыта (f = 1/(25(x^2+y^2)+1), n = 30 узлов по
каждой переменной, максимум |f - P| по сетке 150x150):

    равномерные узлы:  1.77e+06     <- полностью бессмысленный результат
    узлы Чебышёва:     9.93e-03

(2) Порядок узлов. Сам многочлен от порядка узлов не зависит, а вот
ВЫЧИСЛЕНИЯ зависят: разделённые разности и схема Горнера в форме Ньютона
при монотонном (по возрастанию) порядке узлов численно неустойчивы, и уже
при n около 30 погрешности округления начинают расти лавинообразно.
Лечится это перестановкой узлов в последовательность Лежа: очередным
берётся узел, максимально удалённый (в смысле произведения расстояний) от
уже выбранных. Опыт (максимум |f - P|, узлы Чебышёва, [-1,1]x[-1,1]):

     n    монотонный порядок     порядок Лежа
     8      1.20e-03               1.20e-03        f = e^(x^2-y^2)
    16      2.66e-09               2.66e-09
    24      2.33e-13               2.22e-15
    32      2.49e-05               2.22e-15
    40      1.33e+03               2.22e-15
    50      2.47e+13               3.77e-15
    64      5.23e+27               5.55e-15

     n    монотонный порядок     порядок Лежа
    16      1.42e-01               1.42e-01        f = 1/(25(x^2+y^2)+1)
    32      7.97e+01               6.72e-03
    50      8.11e+11               1.93e-04
    64      1.73e+25               1.20e-05

То есть без Лежа-порядка при nx = ny = 32 программа уже рисует мусор, а с
ним всё остаётся на уровне машинной точности. Перестановка стоит O(n^2)
действий и делается один раз при построении узлов.


--------------------------------------------------------------------------------
6. КАК РИСУЕТСЯ ТРЁХМЕРНАЯ КАРТИНКА
--------------------------------------------------------------------------------

Никакого OpenGL - всё считается руками и рисуется QPainter.

(1) Поверхность заменяется сеткой mx x my точек на отображаемом
прямоугольнике; в каждой точке считается значение текущего режима (f, P
или f - P). Заодно находятся min_z и max_z - по ним делается масштаб по
вертикали и выводится max{|F|} = max{|min_z|, |max_z|}.

(2) Координаты нормируются в куб [-1,1]^3: x и y - по границам
отображаемой области, z - по [min_z, max_z]. Поэтому картинка никогда не
вылезает за окно и никогда не оказывается слишком мелкой, а масштабы по
осям независимы.

(3) Проекция. Камера задаётся двумя углами: phi (поворот вокруг оси Z,
клавиши 8 и 9) и theta (подъём над плоскостью, клавиши Up и Down). Орты
экрана:

    вправо:  r = (-sin phi,  cos phi, 0)
    вверх:   u = (-sin theta cos phi, -sin theta sin phi, cos theta)
    на нас:  n = ( cos theta cos phi,  cos theta sin phi, sin theta)

Экранные координаты точки P - это (P, r) и (P, u), а "глубина" - (P, n).
Проекция ортогональная (параллельная), поэтому прямоугольная сетка остаётся
сеткой, и картинка читается лучше, чем при перспективе.

(4) Видимость - алгоритм художника: все клетки сетки сортируются по
глубине своего центра и рисуются от дальних к ближним, так что ближние
закрывают дальние. Цвет клетки зависит от её высоты (синий - низ,
красный - верх), при небольших сетках дополнительно рисуются рёбра.
Сложность одного кадра: O(mx*my log(mx*my)) на сортировку.

(5) Каркас области (ящик) рисуется серым, у его углов подписаны границы по
x, y и значения min_z, max_z.


--------------------------------------------------------------------------------
7. ПРОВЕРКИ
--------------------------------------------------------------------------------

(a) Интерполяция действительно точная в узлах. Для всех восьми функций при
    nx = ny = 5 максимум |P(x_i,y_j) - f(x_i,y_j)| по всем узлам не
    превосходит 1e-15 (машинная точность).

(b) Точность на многочленах. Многочлен, построенный по nx x ny узлам,
    точен на любом многочлене степени <= nx-1 по x и <= ny-1 по y.
    Опыт на [-1,1]x[-1,1], nx = ny = 5, максимум |f - P| по сетке 120x120:

        f = 1                    0.0e+00
        f = x                    1.1e-16
        f = y                    1.1e-16
        f = x + y                4.4e-16
        f = x^2 + y^2            8.9e-16
        f = sqrt(x^2+y^2)        1.3e-01   (не многочлен, в нуле негладкая)
        f = e^(x^2-y^2)          2.4e-02
        f = 1/(25(x^2+y^2)+1)    4.1e-01

(c) Сходимость при росте числа узлов ([-1,1]x[-1,1], узлы Чебышёва +
    порядок Лежа, максимум |f - P| по сетке 120x120):

        n = nx = ny     e^(x^2-y^2)      1/(25(x^2+y^2)+1)
             4           2.42e-01          8.43e-01
             8           1.20e-03          5.31e-01
            16           2.66e-09          1.42e-01
            32           2.66e-15          6.72e-03
            50           2.89e-15          1.93e-04

    Для аналитической функции e^(x^2-y^2) сходимость экспоненциальная: уже
    при 32 узлах достигается машинная точность. Для функции Рунге сходимость
    заметно медленнее, но она есть (на равномерных узлах её бы не было).

(d) Скорость. Самый тяжёлый режим (nx = ny = 64 узла, сетка 128 x 128):

        построение коэффициентов c_ij ......... < 0.001 с
        пересчёт всей поверхности (переключение
        режима, 16384 точки по O(nx*ny) каждая)  0.22 с
        отрисовка кадра ....................... 0.04 с

(e) Проверка на устойчивость интерфейса: прогон, в котором для всех восьми
    функций последовательно нажимаются все клавиши (режимы, узлы, сетка,
    масштаб, возмущение, повороты) - около 400 перестроений - проходит без
    падений, без NaN и без зависаний.


--------------------------------------------------------------------------------
8. ЗАМЕЧАНИЯ
--------------------------------------------------------------------------------

1. Возмущение (клавиши 6 и 7) добавляется к значению функции в центральном
   узле интерполяции, после чего многочлен строится заново. График самой
   функции f при этом не меняется, поэтому в режиме погрешности сразу видно,
   как одна испорченная точка "размазывается" многочленом по всей области -
   это принципиальное отличие многочленной интерполяции от кусочной.

2. Клавиши 2 и 3 меняют только ОТОБРАЖАЕМУЮ область; узлы интерполяции
   остаются на исходном прямоугольнике [a,b] x [c,d] (как и в одномерном
   задании). Поэтому при сильном уменьшении масштаба видно, как многочлен
   уходит вразнос за пределами области интерполяции - это нормальное
   поведение экстраполяции многочленом.

3. Условия к заданию в явном виде нет, поэтому интерфейс сделан по образцу
   одномерного задания (те же клавиши 0-7 с тем же смыслом) и по образцу
   программы из папки task3: те же восемь функций, те же аргументы
   командной строки a b c d nx ny mx my k, те же три режима отображения.
